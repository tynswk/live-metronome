# Live Metronome

iPhone / iPad をライブ本番で使う前提のメトロノーム。画面全体のフラッシュが主表示で、音は任意。
PWA なので「ホーム画面に追加」すると全画面・オフラインで単体アプリのように動く。

## できること

- **画面全体が点滅**。1拍目とそれ以外で色を変えられる（色は自由に指定）。「1拍目だけ光らせる」も可。
- **音は任意**。ON/OFF と音量。消しても光は出る。
- **プリセット8個をワンタップ切替**。BPM・拍数・音価・曲名を保存。長押しで編集。
  切替時に小節頭からリスタートするかは設定で選べる。
- **拍子**：拍数 1〜16、音価 4分/8分/付点4分。各拍を「強 / 弱 / 無音」で編集できるのでクラーベ的な鳴らし方も可。
- **刻み**：1拍を 2/3/4 分割して裏を鳴らす（光るのは拍のみ）。
- **タップテンポ**、BPM ±1（長押しで連続）。
- **PDF譜面**。読み込むと画面が分割され、譜面が出ていない側が光る。分割比は仕切りをドラッグ、
  上下（横位置）の入替も可。ページ送り、テンポに関係なく一定速の自動スクロールあり。
  読み込んだ譜面は端末内（IndexedDB）に残るので次回起動時もそのまま。
- **画面を消さない**（Wake Lock）。バックグラウンド復帰時は位相を作り直して詰まった音の連発を防ぐ。

## 安定性のための設計

- 拍の時刻は **AudioContext.currentTime だけ**で決めている。`setInterval` / `requestAnimationFrame` は
  「先の拍を予約しに行く」トリガーにすぎないので、UI が一瞬詰まってもテンポはずれない。
- 先読み 160ms で予約。スケジューラは **Web Worker のタイマー**と **rAF** の両方から呼ばれる（冪等）。
  片方が止まってももう片方が回す。
- スリープ復帰などで時計が大きく飛んだら、溜まった拍を一気に鳴らさず位相を張り直す。
- PDF は表示中±1画面ぶんだけ描画し、離れたページは canvas を捨てる（全ページ展開しない）。

## 使い方（本番前に一度やること）

1. HTTPS で配信されている URL を iPhone / iPad の **Safari** で開く。
2. 共有ボタン → **ホーム画面に追加**。
3. ホーム画面のアイコンから起動して、一度 **▶ を押す**（iOS はユーザー操作なしに音を出せないため、
   ここで音の準備が済む）。以後はオフラインでも起動する。

> 注意：iOS の**消音スイッチが ON だとクリック音は鳴らない**。光だけで使うか、消音を解除しておく。
> 本番でイヤモニ／PA に送るなら有線かBluetoothで出力先を確認しておくこと（Bluetooth は遅延が乗る）。

## PDF 表示ライブラリ（vendor）

PDF 表示には pdf.js 4.10.38 を使う。`vendor/` に配置済み。

- `vendor/pdf.js`        ← 配布物の `build/pdf.min.mjs`
- `vendor/pdf.worker.js` ← 配布物の `build/pdf.worker.min.mjs`

**拡張子を `.mjs` のままにしない。** Python の `http.server` など一部のサーバーは `.mjs` を
`text/plain` で返し、モジュールとして読み込めずに PDF 機能だけ死ぬ（実際にそうなった）。
中身は ES モジュールのままでよく、`import()` で読むので拡張子は関係ない。

無くてもメトロノームとしては動く（PDF を読み込もうとしたときに設定画面へ案内が出る）。

## 配信

Wake Lock も Service Worker も **HTTPS（または localhost）でしか動かない**。
`http://192.168.x.x` で開くと、画面が勝手に暗くなるしオフラインにもならない。

- **推奨：GitHub Pages**。リポジトリに push して Pages を有効にすれば固定 URL が手に入り、
  ホーム画面に追加したあとは完全オフラインで動く。
- PC での動作確認だけなら `serve.bat`（`http://localhost:8080`）で十分。localhost は secure context 扱い。
